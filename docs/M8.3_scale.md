# M8.3 — what a 34-genome run costs

**What this is.** The scale measurement ROADMAP's M8.3 asks for ("batch test 10–50+ genomes —
record memory/time limits"), run on the **Điềm corpus**: 34 Iridaceae plastomes, all 150–165 kb,
pinned under `.panel/iridaceae-34/` (PROJECT.md §8.31). Every number below is a measurement on
this machine, taken with `/usr/bin/time -v` and `--force` (the run cache keys on `module_version`,
not on a module's source — H-08 — so a cached run would time a lookup and report a lie).

**The machine, stated once, because a scale number without one is not a number.** Intel
i7-1165G7 @ 2.80 GHz, 6 vCPU visible to WSL2, **8,135,488 kB RAM** (~7.8 GB) with ~4 GB available.
This is an ordinary laptop-class CPU and the memory ceiling the project already recorded in
PROJECT.md §9.28 — the toolkit's stated target, not a workstation.

**How it was run.** One module at a time, `plastid run -m <module> -i <genome …>`, reference first.
Single-genome modules (arity 1) were run once per genome — 34 runs per module — and the table
reports the total for all 34 together with the highest peak RSS seen in any of them. Multi-genome
modules took the reference plus the other 33 in one run.

## The nine single-genome modules, all 34 genomes

| Module | 34 runs, wall clock | Peak RSS |
|---|---|---|
| `genome_stats` | 20.5 s | 87 MB |
| `structure` | 21.6 s | 87 MB |
| `introns` | 21.9 s | 87 MB |
| `ssr` (MISA, vendored) | 25.5 s | 87 MB |
| `codon_usage` | 22.8 s | 87 MB |
| `amino_acid` | 23.9 s | 87 MB |
| `orf` | 12.9 s | 51 MB |
| `gene_table` | 15.3 s | 51 MB |
| `submission` | 12.7 s | 52 MB |

**A whole panel of these is a coffee break, not a batch job** — a quarter of a minute per module
for all 34 genomes, and 87 MB at the worst. The 87 MB is not a coincidence: it is the cost of one
Biopython GenBank parse of a ~300 kB record, and it is the same for every module that reads genes.

## The expensive shape: one whole-genome MAFFT alignment

Three modules align the reference **plus every genome, whole**: `substitutions` (its default
`scope=whole`), `diversity` and `barcodes`. The curve below is **measured on `substitutions`**;
`diversity` and `barcodes` were measured separately on 10/10/2026 — see
"The two whole-genome modules, measured at 34" at the end of this file. `substitutions` also has a second scope — `cds`, per-gene — which is the
one the manuscripts quote; both are below, on the same 34 sequences.

| `substitutions` scope | Genomes | Wall clock | Peak RSS | Outcome |
|---|---|---|---|---|
| `whole` (default) | 4 | 1 min 12 s | 91 MB | completed |
| `whole` (default) | 8 | 2 min 44 s | 97 MB | completed |
| `whole` (default) | 16 | — | — | **exceeded 7 minutes**, stopped |
| `whole` (default) | 34 | — | — | **exceeded 11 minutes**, stopped |
| **`cds`** | **34** | **5 min 24 s** | **179 MB** | **completed** |

**The limit here is patience, not RAM.** A whole-genome alignment of 34 plastomes peaks under
100 MB on a machine with 8 GB free — the memory ceiling this project worried about (§9.28) is not
what stops it. What stops it is that MAFFT's progressive alignment over 5.2 Mbp of sequence at this
divergence takes tens of minutes on one core, and its cost grows faster than the genome count: 4 →
8 genomes doubles the time, 8 → 16 more than doubles it again.

**The affordable path is the one the manuscripts already use.** `substitutions --set scope=cds`
returns before the whole alignment is built (module code: `if scope == "cds": return _cds_scope(...)`)
and aligns per gene instead. That is the **CDS-only · shared genes · IR excluded** scope of §6's
golden Ts/Tv, and it is the number the two manuscripts quote. The same 34 genomes, the same module,
the same sequences: **5 min 24 s and it finishes**, against a whole-genome alignment that had not
finished after 11 minutes. It costs more memory than the whole scope (179 MB against 97 MB, because
it holds 79 per-gene alignments) and it is the only one of the two that completes — on a machine
with 8 GB, memory is the cheaper currency.

## The per-pair modules at 34

| Module | Genomes | Tool calls | Wall clock | Peak RSS |
|---|---|---|---|---|
| `synteny` (`nucmer` → `delta-filter` → `show-coords` per query) | 34 | 99 | **19.6 s** | 145 MB |
| `popgen` (MAFFT per gene; every statistic written here) | 34 | 80 | **6 min 13 s** | 179 MB |
| `kaks` (MAFFT + `yn00` per shared gene per pair) | 34 | 5,202 MAFFT + 4,766 yn00 = **9,968** | **8 min 26 s** | 98 MB |

`synteny` aligns 33 query genomes against the reference with `nucmer` and finishes in **under twenty
seconds** — 145 MB, three tool calls per query. `popgen` aligns per gene (80 calls) and does every
statistic itself in **6 min 13 s**, holding all of it at 179 MB. `kaks` scores every gene the
reference and a query share, pair by pair: **5,202 alignments and 4,766 `yn00` runs**, each over two
sequences, in **8 min 26 s**. Its run reports 33 genomes compared, 80 genes considered, 74 shared
with every annotated genome.

**That is the finding worth keeping: call count is not what costs.** 9,968 alignments of two short
sequences finish in 8 min 26 s; *one* alignment of 34 whole plastomes had not finished in 11. What
costs is the size of a single alignment, not how many calls there are — so a module's price cannot
be read off its loop structure, which is exactly why this pass measured instead of estimating (the
estimate written here first said "about 2,600 of each"; the measurement says 5,202 and 4,766, and
the 33 `nucmer` calls of `synteny` were expected to be the slow half and turned out to be the fast
one).

## What this means for a real run

* **Single-genome work does not need batching.** 34 genomes × 9 modules is under four minutes and
  under 100 MB.
* **A whole-genome alignment is comfortable to 8 genomes and not much past it** (2 min 44 s at 8;
  over 7 minutes at 16). Above that, use the per-gene scope — which is what the comparison tables
  for the manuscripts quote anyway, and which does all 34 in **5 min 24 s**.
* **Many small tool calls are cheap and many-alignments-per-pair modules scale fine**: `kaks` made
  **9,968** calls across the panel in **8 min 26 s**. A per-pair design is not the thing to avoid;
  an alignment of 34 whole plastomes is.
* **The corpus is the first dataset that could fail.** Two of its 34 records killed a whole run
  before this measurement was half done (`structure` on a 3 bp trailing window, `orf` on a record
  that annotates `rps16` twice) — PROJECT.md §9.I. Neither shape exists in the data this project
  picked for itself, because it picks records that work.

## The two whole-genome modules, measured at 34 — the gap this file used to name

Measured **10/10/2026 (P8-04)** on the same machine and the same protocol as every number above:
one module at a time, the same 34 pinned records with the golden first, `--force`,
`/usr/bin/time -v`. This is the pair the earlier version of this file left as *not measured* —
correctly, because the prediction came from reading their code rather than from running them.

| Module | Genomes | Wall clock | Peak RSS | Outcome |
|---|---|---|---|---|
| `diversity` | 34 | **13 min 14 s** | **138 MB** | completed — π **0.040086** over 120,964 usable columns of a 191,707-column alignment; SSC 0.1211 · LSC 0.0439 · IRa 0.0135 · IRb 0.0136 |
| `barcodes` | 34 | **12 min 27 s** | **138 MB** | completed — mean π 0.050020 over 859 windows, 13 hypervariable regions, **10 candidate loci, 8 found** |

**The prediction was wrong in the direction that matters.** "Not measured" was written because
these two call the same whole-genome alignment as `substitutions`, whose `scope=whole` at 34 was
stopped after 11 minutes — so the honest guess was that they would not finish either. They do, in
about **13 minutes**, and at the same 138 MB. The reason is the one this file already measured
elsewhere: what costs is the size of a single alignment, and an alignment of 34 plastomes is
expensive but finite — the earlier entry recorded a run that was *stopped at a cap*, not a run
that failed. A cap is not a measurement.

**What this file left open is closed — and what it never covered is named rather than implied.**
`diversity` and `barcodes` were its only two entries marked *not measured*, and both now have a
row. It is not a table of every module the toolkit has: **`repeats`** (built later, P2B-02),
**`stats`**, and the annotation and naming path (`plastid_annotate` · `mito_annotate` ·
`mito_genes` · `gene_names` · `gene_normalize`) have **no scale row here**, which is the honest
alternative to letting *"nothing is left not measured"* read as *"everything was measured"*. The
number to remember is the boring one: **the whole 34-genome panel costs about a quarter of an hour
and under 150 MB**, whichever whole-genome module you run on it.
