# Things we don't do (M9.5)

**Why this file exists.** Every one of these is a question a user will ask, and a wrong expectation
formed early is worse than a refusal: it produces a run that looks finished and answers something
else. Each item below says **what is not there**, **why** (with the measurement where there is
one), and **what to do instead**.

| We don't… | Why | Instead |
|---|---|---|
| **Run natively on Windows** | The tool chain is Linux/conda; a native port would mean a second, differently-pinned tool environment, and §9.B-14 measured what that costs — two MAFFT builds, two Ts/Tv numbers from one genome | **Windows through Docker** (official): build `docker/Dockerfile`, run everything inside it (`docs/platforms.md`) |
| **Promise macOS** | No Mac has ever run this. The pure-Python path should work and every pinned tool exists for osx-64/arm64 — *should* is not measured | Treat the macOS column as **experimental, unverified** (`docs/platforms.md`); report what you see |
| **Assemble a genome from reads** | There is no assembly module. It waits on **real Illumina/ONT reads**, which the project does not have yet — its oldest blocker (ROADMAP → Waiting) | Start from a GenBank/FASTA genome: sequencing facility, GenBank, or your own assembler. Everything downstream works on the assembled record |
| **Predict RNA editing without RNA-seq** | An edit is a C→U change in the transcript, invisible in the DNA. Called from DNA alone it is a guess dressed as an annotation — and this project's own golden annotation needed an RNA-edited start handled explicitly (`/exception`, §8.18) | Annotate with the reference transfer (which reports what the reference says), and treat editing as the PI's analysis on real RNA data |
| **Align a large panel whole** | Measured (M8.3): `substitutions scope=whole` was comfortable at **8 genomes (2 min 44 s)** and **had not finished at 16 after 7 minutes** | Use the per-gene scope — `substitutions --set scope=cds` does **34 genomes in 5 min 24 s**, and it is the scope the manuscripts quote |
| **Mix organelles in one run** | One run serves one organelle; a plastome module run on a mitogenome would describe a genome it never read (CLAUDE.md → "Two organelles, one per run") | Run plastid and mito records separately. The one named exception is the cross-compartment transfer analysis, which does not exist yet (parked) |
| **Analyse mitochondria beyond the prototype** | `mito annotate` and `mito genes` exist and stay exactly as they are; the mito round (NUPT/MTPT, mito structural polymorphism, plastid–mito comparison) is **parked by scope** — this round is plastid only | Use the two mito modules if a mitogenome is what you have; do not expect the parked analyses |
| **Do divergence time or ancestral-state analysis** | Deleted from the plan (10/10/2026, §13.6): those need a tree, fossil calibrations and a scientific question — the PI's analyses, with her own tools | `mcmctree` / BEAST2, as the project's own PI does |
| **Ship every tool it can call** | Licence, not laziness: MISA's zip states no licence, Vmatch is academic-only, table2asn is a 56 MB NCBI download — none of them may be redistributed inside this package (D-q, `docs/licensing.md`) | Each is declared with its exact install line: `docs/tools/`. A missing tool is always **named**, never silently skipped |
| **Answer a genome with no IR pair** | The IR gate: the two inverted-repeat copies must be ≥ 99.9 % identical before any position-based analysis. Naive detection got 2 of 9 published plastomes wrong and said nothing (§8.3) | If the gate stops you, the record is the problem — check that it is a plastome and that its IR copies really match; amplicons and fragments are refused **by design** (§8.72) |
| **Draw a multi-species junction figure from a table** | A figure here reads table cells and never recomputes — but the species order of the manuscript's Figure 2 comes from a **tree**, and the genes drawn on each side of a junction come from the **record's own annotation**. Neither is a cell, so this one figure can only be drawn by an external program reading the records themselves (CPJSdraw, `docs/tools/cpjsdraw.md`) | Named here so nobody looks for it in the figure catalogue and concludes the toolkit is broken. `plastid ir-junction` drives CPJSdraw on the records themselves (M10.1) |
| **Build a phylogenetic tree** | The maximum-likelihood tree behind the manuscript's Figure 9 is **IQ-TREE's**, run by the user over their own supermatrix: inferring one means choosing a model, partitions and support values — an analysis in its own right, and the PI's call, not a by-product of a plastome run | Draw a tree **you** built: `plastid figures <run> --figure r_tree --set tree=<file.treefile>`. The file is handed to the script as its input, never copied into the run, and its sha256 goes in the caption instead of a scope label — the figure read no table, and says so. Note the script drops two *Asparagus* tips and roots on two Orchidaceae by default |
| **Draw a multi-species RSCU / amino-acid / SSR figure from one run** | Those three come from **arity-1** modules — `codon_usage`, `amino_acid` and `ssr` take exactly one genome per run — so their R figures carry **one species column**, and the run layer concatenates nothing across runs (measured 17/10/2026). The manuscript's 34-species panels were assembled from 34 separate runs by CGAS, outside this toolkit | Run the module once per genome and assemble the panels outside, or read each run's own figure. The Ka/Ks and π figures have no such limit: `kaks` and `diversity` take the whole panel in one run, so those two figures cover every genome the run holds |
| **Draw the twelve substitution types for a run in the CDS scope only** | Both scopes publish `substitutions_by_type` (added 17/10/2026), but the CDS scope only compares genomes that **carry an annotated CDS** — a record without annotation is left out and named, so its type columns do not exist | Use the whole-alignment scope (`--set scope=whole`, the default) when every record must appear. The figure skips by name when the two tables disagree about which genomes they cover |
| **Offer a web interface** | Deferred until the core is stable (M9.7). A UI is a second product to keep correct, and this round's job is a release people can cite | The command line, and `docs/` for guidance |
| **Run "quickly" on a big panel — in general** | Measured on the stated machine (M8.3): the whole 34-genome panel costs **about a quarter of an hour and under 150 MB** per whole-genome module; single-genome work over the same panel is under four minutes | Budget accordingly, and remember what costs is the size of a *single* alignment, not the number of tool calls: 9,968 calls finished in 8 min 26 s (`kaks`) |
