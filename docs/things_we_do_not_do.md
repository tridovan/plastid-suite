# Current scope and limits

This file describes current behavior and scope. Planned improvements are not implemented features.
Reproduced defects are listed separately in [known issues](known_issues.md); a limitation described
here is not automatically intentional or permanent.

**Why this file exists.** Every one of these is a question a user will ask, and a wrong expectation
formed early is worse than a refusal: it produces a run that looks finished and answers something
else. Each item below says **what is not there**, **why** (with the measurement where there is
one), and **what to do instead**.

| We don't… | Why | Instead |
|---|---|---|
| **Run natively on Windows** | The tool chain is Linux/conda; a native port would mean a second, differently-pinned tool environment, and a measurement showed what that costs — two MAFFT builds, two Ts/Tv numbers from one genome | **Windows through Docker** (official): build `docker/Dockerfile`, run everything inside it (`docs/platforms.md`) |
| **Promise macOS** | No Mac has ever run this. The pure-Python path should work and every pinned tool exists for osx-64/arm64 — *should* is not measured | Treat the macOS column as **experimental, unverified** (`docs/platforms.md`); report what you see |
| **Assemble nanopore reads, or a mitochondrial genome** | `plastid assemble` takes paired short reads or PacBio HiFi reads and assembles a plastome. Oatk takes HiFi only, and a mitogenome is outside this round's plastid scope | Assemble elsewhere and start from the FASTA. Everything downstream works on the assembled record |
| **Call an assembly finished because the assembler closed a path** | A closed path is a claim. A published circular *Laurus nobilis* record has two joins no read crosses, and it reads as complete to anything that only checks for one sequence. On *Picea abies* 15 arrangements close through the graph, with the same reads crossing every join of each, and the assembler's first path is not the published one | `plastid assemble` maps the reads back with an aligner the assembler does not use. A join the reads do not cross is **undetermined**, the graph is read for how many structures close through it, and only a supported sequence with a resolved graph is declared as an artifact for the next step |
| **Upload your data to a web service by itself, or switch to one silently** | Unpublished reads are the user's to share, and a run that quietly ran somewhere else would carry provenance that is not true | A heavy tool runs locally first. When it cannot (the tool is missing, or the machine is too small for the input) the run stops with a named error and the prepare → import route: run the tool on the service yourself and import its result, which is checked and labelled with where it ran (assembly, Phase 7, is built this way) |
| **Call RNA editing from reads, or present a prediction as original PREP-Cp output** | The `rna_editing` module predicts C-to-U sites with the published PREP method against a rebuilt reference (B′); the original PREP-Cp service ended in 2022 and its alignments were never published, so no output can be the original's. Calling editing from RNA-seq reads is a different method with its own scope | Use `plastid run -m rna_editing` for **predicted · PREP-Cp-compatible** sites ([specification](tools/prep_cp.md)), and treat RNA-seq or RT-PCR as the independent check, never as the prediction's input |
| **Align a large panel whole** | Measured (M8.3): `substitutions scope=whole` was comfortable at **8 genomes (2 min 44 s)** and **had not finished at 16 after 7 minutes** | Use the per-gene scope — `substitutions --set scope=cds` does **34 genomes in 5 min 24 s**, and it is the scope of the golden Ts/Tv |
| **Mix organelles in one run** | One run serves one organelle; a plastome module run on a mitogenome would describe a genome it never read | Run plastid and mito records separately. The one named exception is the cross-compartment transfer analysis, which does not exist yet (parked) |
| **Analyse mitochondria beyond the prototype** | `mito annotate` and `mito genes` exist and stay exactly as they are; the mito round (NUPT/MTPT, mito structural polymorphism, plastid–mito comparison) is **parked by scope** — this round is plastid only | Use the two mito modules if a mitogenome is what you have; do not expect the parked analyses |
| **Do divergence time or ancestral-state analysis** | Deleted from the plan (10/10/2026): those need a tree, fossil calibrations and a scientific question — the PI's analyses, with her own tools | `mcmctree` / BEAST2, as the project's own PI does |
| **Ship every tool it can call** | Licence, not laziness: MISA's zip states no licence, Vmatch is academic-only, table2asn is a 56 MB NCBI download — none of them may be redistributed inside this package (D-q, `docs/licensing.md`) | Each is declared with its exact install line: `docs/tools/`. A missing tool is always **named**, never silently skipped |
| **Run a position-based module on a record whose inverted repeat fails the gate** | A position-based number reads the two copies as one repeat, so every module marked `IR = yes` in [the module table](platforms.md) needs them measured ≥ 99.9 % identical. A module that reads only CDS sequences needs no gate and runs without it | Read the copy locations the refusal and the manifest give. When the record's annotation is what disagrees, `--set ir_source=sequence` reads the repeat from the sequence; otherwise correct the record's `repeat_region`. The gate itself stays closed |
| **Find an inverted repeat outside 10–35 kb from sequence alone** | The sequence search accepts a repeat between 10 and 35 kb. Two panel records with IRs of 38.2 and 43.6 kb are refused by name rather than answered wrongly | Use a record that annotates its repeat: the annotation path has no such window |
| **Draw a native multi-species junction figure yet** | The current `plastid ir-junction` route drives CPJSdraw on annotated records. A native figure needs validated feature locations and optionally a tree for ordering; it is not inherently limited to a table-only input | Use the current external route with its documented requirements |
| **Choose an outgroup or root the tree for you** | `phylogeny` (M11.21) infers an unrooted ML tree and writes the `.treefile`; rooting needs a taxon the user names, and the toolkit does not infer one from taxonomy (the K-06 lesson) | Pass `--set root/outgroup` to the `r_tree` figure, or root the tree in your own tool. The module reports the topology it built and cannot say the tree is *right* — a topology is not a verifiable number |
| **Draw a multi-species RSCU / amino-acid / SSR figure from one `plastid run`** | Those three come from **arity-1** modules — `codon_usage`, `amino_acid` and `ssr` take exactly one genome per run — so one run's figure carries **one species column** | `plastid batch` runs them over every genome and aggregates the tables; `plastid figures <batch-dir>`, or `--figures` on the batch, draws one column per sample. The Ka/Ks and π figures have no such limit: `kaks` and `diversity` take the whole panel in one run |
| **Draw the twelve substitution types for a run in the CDS scope only** | Both scopes publish `substitutions_by_type` (added 17/10/2026), but the CDS scope only compares genomes that **carry an annotated CDS** — a record without annotation is left out and named, so its type columns do not exist | Use the whole-alignment scope (`--set scope=whole`, the default) when every record must appear. The figure skips by name when the two tables disagree about which genomes they cover |
| **Host a web service** | Unpublished data must not need uploading. `plastid ui` runs on your own computer, on `127.0.0.1`, and sends nothing anywhere | `plastid ui`, or the command line. Both write the same run directories |
| **Run "quickly" on a big panel — in general** | Measured on the stated machine (M8.3): the whole 34-genome panel costs **about a quarter of an hour and under 150 MB** per whole-genome module; single-genome work over the same panel is under four minutes | Budget accordingly, and remember what costs is the size of a *single* alignment, not the number of tool calls: 9,968 calls finished in 8 min 26 s (`kaks`) |
