# Current scope and limits

This file describes current behavior and scope. Planned improvements are not implemented features.
Reproduced defects are listed separately in [known issues](known_issues.md); a limitation described
here is not automatically intentional or permanent.

**Why this file exists.** Every one of these is a question a user will ask, and a wrong expectation
formed early is worse than a refusal: it produces a run that looks finished and answers something
else. Each item below says **what is not there**, **why** (with the measurement where there is
one), and **what to do instead**.

| We don't… | Why | Instead |
|---|---|---|
| **Run natively on Windows** | The tool chain is Linux/conda; a native port would mean a second, differently-pinned tool environment, and a measurement showed what that costs — two MAFFT builds, two Ts/Tv numbers from one genome | **Windows through Docker** (official): build `docker/Dockerfile`, run everything inside it (`docs/platforms.md`) |
| **Promise macOS** | No Mac has ever run this. The pure-Python path should work and every pinned tool exists for osx-64/arm64 — *should* is not measured | Treat the macOS column as **experimental, unverified** (`docs/platforms.md`); report what you see |
| **Assemble a genome from reads** | There is no assembly module yet. It is planned after the inverted-repeat rework, and will be judged on a published paper's public reads against that paper's own assembled plastome | Start from a GenBank/FASTA genome: sequencing facility, GenBank, or your own assembler. Everything downstream works on the assembled record |
| **Provide an RNA-editing module yet** | M4.5 has selected original PREP-Cp, cutoff 0.8; preparation/import/mapping and a genuine engine run are not implemented or verified. An earlier minimap2/samtools simulation is not this integration | Follow the [PREP-Cp specification](tools/prep_cp.md). Prediction takes annotated CDS, not mandatory RNA-seq; the selected public RNA-seq/site dataset supplies independent validation. PTS will retain original results and predicted labels rather than implement a substitute predictor |
| **Align a large panel whole** | Measured (M8.3): `substitutions scope=whole` was comfortable at **8 genomes (2 min 44 s)** and **had not finished at 16 after 7 minutes** | Use the per-gene scope — `substitutions --set scope=cds` does **34 genomes in 5 min 24 s**, and it is the scope of the golden Ts/Tv |
| **Mix organelles in one run** | One run serves one organelle; a plastome module run on a mitogenome would describe a genome it never read | Run plastid and mito records separately. The one named exception is the cross-compartment transfer analysis, which does not exist yet (parked) |
| **Analyse mitochondria beyond the prototype** | `mito annotate` and `mito genes` exist and stay exactly as they are; the mito round (NUPT/MTPT, mito structural polymorphism, plastid–mito comparison) is **parked by scope** — this round is plastid only | Use the two mito modules if a mitogenome is what you have; do not expect the parked analyses |
| **Do divergence time or ancestral-state analysis** | Deleted from the plan (10/10/2026): those need a tree, fossil calibrations and a scientific question — the PI's analyses, with her own tools | `mcmctree` / BEAST2, as the project's own PI does |
| **Ship every tool it can call** | Licence, not laziness: MISA's zip states no licence, Vmatch is academic-only, table2asn is a 56 MB NCBI download — none of them may be redistributed inside this package (D-q, `docs/licensing.md`) | Each is declared with its exact install line: `docs/tools/`. A missing tool is always **named**, never silently skipped |
| **Run modules requiring IR without a detected pair passing the gate** | Those modules currently require ≥99.9% measured identity. The detector and identity measurement have known defects, so both a pass and a refusal can be misleading | Inspect the copy locations and full-copy comparison; do not assume a refusal proves the input is wrong. See K-01/K-03/K-04 in [known issues](known_issues.md). Restricting the gate to modules that actually need IR is planned |
| **Trust a de-novo IR on a sequence with a single-base indel in the repeat** | K-07, open: one inserted or deleted base inside a copy can make the detector report **half** the repeat at 100 %, which passes the gate. A run on such a FASTA exits 0 and every position-based table is built on the wrong interval, with nothing in the output saying so | Do not hand an unannotated assembly to the position-based modules without checking the IR length against a relative's own annotation. Where the record carries a `repeat_region`, the annotation path is used and is not affected. The regression is `tests/unit/test_ir_indel_collapse.py` |
| **Draw a native multi-species junction figure yet** | The current `plastid ir-junction` route drives CPJSdraw on annotated records. A native figure needs validated feature locations and optionally a tree for ordering; it is not inherently limited to a table-only input | Use the current external route with its documented requirements, or wait for the planned native implementation. Validate coordinates independently because the current junction reader also has defects |
| **Choose an outgroup or root the tree for you** | `phylogeny` (M11.21) infers an unrooted ML tree and writes the `.treefile`; rooting needs a taxon the user names, and the toolkit does not infer one from taxonomy (the K-06 lesson) | Pass `--set root/outgroup` to the `r_tree` figure, or root the tree in your own tool. The module reports the topology it built and cannot say the tree is *right* — a topology is not a verifiable number |
| **Draw a multi-species RSCU / amino-acid / SSR figure from one run** | Those three come from **arity-1** modules — `codon_usage`, `amino_acid` and `ssr` take exactly one genome per run — so their R figures carry **one species column**, and the run layer concatenates nothing across runs (measured 17/10/2026). The Iridaceae paper's 34-species panels were assembled from 34 separate runs by CGAS, outside this toolkit (multi-genome output is planned) | Run the module once per genome and assemble the panels outside, or read each run's own figure. The Ka/Ks and π figures have no such limit: `kaks` and `diversity` take the whole panel in one run, so those two figures cover every genome the run holds |
| **Draw the twelve substitution types for a run in the CDS scope only** | Both scopes publish `substitutions_by_type` (added 17/10/2026), but the CDS scope only compares genomes that **carry an annotated CDS** — a record without annotation is left out and named, so its type columns do not exist | Use the whole-alignment scope (`--set scope=whole`, the default) when every record must appear. The figure skips by name when the two tables disagree about which genomes they cover |
| **Offer a web interface** | Deferred until the core is stable (M9.7). A UI is a second product to keep correct, and this round's job is a release people can cite | The command line, and `docs/` for guidance |
| **Run "quickly" on a big panel — in general** | Measured on the stated machine (M8.3): the whole 34-genome panel costs **about a quarter of an hour and under 150 MB** per whole-genome module; single-genome work over the same panel is under four minutes | Budget accordingly, and remember what costs is the size of a *single* alignment, not the number of tool calls: 9,968 calls finished in 8 min 26 s (`kaks`) |
